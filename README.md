## 1. Repository Purpose

This repository contains the source code developed for the MSc dissertation project **“Sugarcane Yield Prediction at Field Level Using Satellite Imagery and Remote Sensing.”**

The project investigates a remote-sensing and deep-learning workflow for estimating sugarcane yield at field level using multi-temporal satellite and environmental observations. Satellite data are extracted through Google Earth Engine (GEE), structured into approximately fortnightly observations, analysed, mapped to field-level annual yield estimates, and then used to train and evaluate a Long Short-Term Memory (LSTM) regression model.

The main workflow is:

1. Extract multi-source satellite and environmental features for sugarcane field polygons.
2. Structure observations at approximately 15-day intervals.
3. Perform exploratory data analysis and data-quality checks.
4. Map USDA state-level annual sugarcane yield rates to field-year yield estimates using field area and standardized satellite-feature deviations.
5. Build sequential feature windows for LSTM modelling.
6. Train, tune and evaluate the LSTM at several in-season prediction checkpoints.

The repository is supplied as supporting evidence for the dissertation and is intended to make the implementation and processing workflow reproducible.

## 9. Reproducing the Project

The notebooks should be run in the following order.

### Step 1 — Google Earth Engine setup

A Google Earth Engine account/project is required.

In `Phase1_USA_Fortnight_Extraction(2).ipynb`:

1. Set `EE_PROJECT` to an Earth Engine/Google Cloud project to which you have access.
2. Set `EE_ASSET` to the field-polygon FeatureCollection.
3. Choose `STATE_FILTER`.
4. Confirm the desired `COLLECTION_YEARS`.
5. For a quick test, set `MAX_FIELDS` to a small value.
6. For the full extraction, set `MAX_FIELDS = None`.
7. Authenticate/initialize Earth Engine when prompted.
8. Run the notebook from top to bottom.

The main extraction mode exports data to the Google Drive folder:

```text
GEE_Fortnight_Exports
```

The notebook combines the exported fortnight CSV files into:

```text
usa_fortnight_features.csv
```

Earth Engine batch exports may take time and depend on Earth Engine quotas and dataset availability.

---

### Step 2 — Exploratory data analysis

Place:

```text
usa_fortnight_features.csv
```

in the same working directory as:

```text
Phase2_Time_Series_EDA(1).ipynb
```

Then run all cells.

This notebook performs:

- dataset-size and field/year checks;
- missing-value analysis;
- time-series plots;
- distribution analysis;
- correlation analysis;
- Sentinel-2 coverage/data-quality checks.

No additional source dataset is required beyond the Phase 1 output.

---

### Step 3 — Field-level yield mapping

Place:

```text
usa_fortnight_features.csv
```

in the working directory of:

```text
Phase3_Yield_Mapping(1).ipynb
```

Run all cells.

Phase 3:

1. cleans the Phase 1 export;
2. selects observations inside the configured sugarcane monitoring season;
3. removes unusable observations according to its quality-control conditions;
4. calculates state/year reference means;
5. standardizes field deviations relative to each state/year distribution;
6. combines weighted satellite/environmental deviations with USDA NASS state yield rates and field area;
7. creates annual field-level mapped yield values;
8. creates cumulative in-season yield estimates.

The principal outputs are:

```text
usa_field_annual_yield.csv
usa_fortnight_yield_mapped.csv
```

The annual yield mapping implemented in this phase uses:

```text
Annual_Yield = Area × State_Annual_Yield × (1 + scalar_difference)
```

where `scalar_difference` is derived from a weighted combination of standardized field-level satellite/environmental feature deviations.

This means the Phase 3 field-level annual target is a **mapped/derived field-level yield estimate based on USDA state yield and satellite variability**, rather than an independently measured harvest value for every individual field.

---

### Step 4 — LSTM yield prediction

Place:

```text
usa_fortnight_yield_mapped.csv
```

in the same directory as:

```text
Phase4_LSTM_Yield_Prediction(1).ipynb
```

Then run all cells.

The LSTM currently uses the following 10 predictor variables:

```text
NDVI
EVI
GNDVI
SAVI
MSAVI
MOISTURE
LAI
NDMI_8
NDWI_8
Elevation
```

The notebook:

1. filters records with the required predictor values;
2. converts mapped total annual yield to yield per acre for model training;
3. separates unique field IDs into training, validation and test groups;
4. fits `StandardScaler` using training data;
5. constructs sequential LSTM input windows;
6. tunes LSTM hyperparameters;
7. trains/evaluates the selected architecture;
8. evaluates several seasonal prediction checkpoints;
9. converts predicted yield-per-acre values back to total field yield using field area;
10. saves model/result outputs and produces diagnostic plots.

The configured prediction checkpoints are:

- Early: June 15
- Mid: July 15
- Late: August 15
- Pre-harvest: September 15
- Full season

The current saved best-parameter file records:

```json
{
  "look_back": 3,
  "learning_rate": 0.001,
  "lstm_units": [32, 32],
  "dropout": 0.2,
  "batch_size": 128
}
```

The corresponding LSTM architecture consists of two LSTM layers followed by dropout and dense regression layers.

- Full Earth Engine extraction can require significant processing time.
